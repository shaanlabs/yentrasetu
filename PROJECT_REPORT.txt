================================================================================
  1. PROJECT OVERVIEW
================================================================================

YantraSetu is India's premier heavy equipment marketplace — a comprehensive,
full-stack web platform that enables buying, selling, and renting of heavy
machinery (construction, mining, agriculture, and industrial equipment),
along with marketplaces for spare parts, certified operators, and mechanics.

The name "YantraSetu" means "Bridge of Machines" (Yantra = Machine,
Setu = Bridge) — symbolizing the platform's role in connecting equipment
owners, buyers, renters, operators, and service providers across India.

Key Highlights:
  • Unified multi-role account system (buyer/seller/renter/operator/mechanic)
  • Location-first discovery with GPS-based radius search
  • ML-powered price prediction and recommendation engine
  • Admin moderation with fraud detection and spam prevention
  • Tiered subscription monetization model
  • End-to-end rental workflow with digital agreements
  • Real-time in-app messaging between buyers and sellers
  • Comprehensive review and trust scoring system
  • UTM campaign tracking and marketing analytics
  • SEO optimization with structured data (JSON-LD)


================================================================================
  2. PROBLEM STATEMENT
================================================================================

India's heavy equipment market (valued at $20+ billion) lacks a unified
digital platform. Currently:

  • Buyers/sellers rely on fragmented local dealers and word-of-mouth
  • No standardized pricing — buyers often overpay or sellers undervalue
  • No verification system — high risk of fraud and fake listings
  • Operators and mechanics have no formal marketplace to showcase skills
  • Rental processes are manual with no digital agreements or tracking
  • Spare parts are difficult to source for specific machinery models

YantraSetu addresses all these problems with a single, trust-based platform.


================================================================================
  3. OBJECTIVES
================================================================================

  1. Create a unified marketplace for heavy machinery buy/sell/rent
  2. Build operator and mechanic hiring marketplaces
  3. Implement ML-based fair price prediction for equipment
  4. Establish a verification and trust system (document verification, reviews)
  5. Enable digital rental agreements with security deposit management
  6. Provide analytics dashboards for market insights
  7. Implement robust security (rate limiting, spam detection, fraud reporting)
  8. Build a subscription-based revenue model for dealers
  9. Deliver SEO-optimized listings with structured data
 10. Support location-based search with geolocation

7.3 MODEL ASSOCIATIONS (SEQUELIZE CODE)
================================================================================

  // User → Listings
  User.hasMany(MachineryListing, { foreignKey: 'userId', as: 'machineryListings' })
  User.hasMany(PartListing, { foreignKey: 'userId', as: 'partListings' })
  MachineryListing.belongsTo(User, { foreignKey: 'userId', as: 'owner' })
  PartListing.belongsTo(User, { foreignKey: 'userId', as: 'seller' })

  // User → Profiles (1:1)
  User.hasOne(OperatorProfile, { foreignKey: 'userId', as: 'operatorProfile' })
  User.hasOne(MechanicProfile, { foreignKey: 'userId', as: 'mechanicProfile' })
  OperatorProfile.belongsTo(User, { foreignKey: 'userId', as: 'user' })
  MechanicProfile.belongsTo(User, { foreignKey: 'userId', as: 'user' })

  // User → Chats (dual FK)
  User.hasMany(Chat, { foreignKey: 'buyerId', as: 'buyerChats' })
  User.hasMany(Chat, { foreignKey: 'sellerId', as: 'sellerChats' })
  Chat.belongsTo(User, { foreignKey: 'buyerId', as: 'buyer' })
  Chat.belongsTo(User, { foreignKey: 'sellerId', as: 'seller' })

  // Chat → Messages
  Chat.hasMany(Message, { foreignKey: 'chatId', as: 'messages' })
  Message.belongsTo(Chat, { foreignKey: 'chatId', as: 'chat' })
  Message.belongsTo(User, { foreignKey: 'senderId', as: 'sender' })

  // User → Reviews (dual FK)
  User.hasMany(Review, { foreignKey: 'reviewerId', as: 'reviewsGiven' })
  User.hasMany(Review, { foreignKey: 'revieweeId', as: 'reviewsReceived' })
  Review.belongsTo(User, { foreignKey: 'reviewerId', as: 'reviewer' })
  Review.belongsTo(User, { foreignKey: 'revieweeId', as: 'reviewee' })

  // User → Bookings (dual FK)
  User.hasMany(RentalBooking, { foreignKey: 'ownerId', as: 'rentalsAsOwner' })
  User.hasMany(RentalBooking, { foreignKey: 'renterId', as: 'rentalsAsRenter' })
  RentalBooking.belongsTo(User, { foreignKey: 'ownerId', as: 'owner' })

9.14 ML / AI INTELLIGENCE MODULE
─────────────────────────────────
  Files: pricePrediction.js, recommendationEngine.js,
         demandForecaster.js, sentimentAnalyzer.js,
         leadScorer.js, mlController.js

  A. PRICE PREDICTION ENGINE
     • Pure JS multivariate linear regression
     • Features: category, condition, type, year, hours, city
     • Auto-trains on startup, re-trains every 6 hours
     • Gradient descent: 500 epochs, learning rate 0.01
     • Log-transformed target for skewed price distribution
     • Fallback: category-based median with condition/age factors
     • Confidence levels: high (50+ samples), medium, low

  B. RECOMMENDATION ENGINE
     • Content-based: similar listings by category, make, price, location
     • Collaborative: "users who viewed X also viewed Y" (via ActivityLog)
     • Location-based: trending near user's location
     • Personalized: combines collaborative + trending, deduplicates

  C. DEMAND FORECASTER
     • Category demand over time (supply vs demand)
     • Price trends by category (avg, min, max per month)
     • Supply-demand gap analysis (high_demand/balanced/oversupply)
     • Seasonal patterns (monthly distribution of listings)

  D. SENTIMENT ANALYZER
     • AFINN-165 lexicon-based scoring (400+ word dictionary)
     • Negation-aware ("not good" = negative)
     • Theme extraction (most frequent content words)
     • Score normalized to -1 to +1 range
     • Labels: positive, slightly_positive, neutral, slightly_negative, negative
     • Machinery-specific vocabulary (leaking, overheating, certified, etc.)

  E. SELLER TRUST SCORE (0-100)
     • Rating component: 0-30 points
     • Review volume: 0-20 points (logarithmic scale)
     • Sentiment consistency: 0-20 points
     • Verification badge: 0-15 points
     • Account tenure: 0-15 points
     • Labels: excellent (80+), good (60+), average (40+), low (20+)

  F. LEAD SCORER (0-100)
     • Profile completeness: 0-20 points
     • Activity recency: 0-25 points
     • Engagement depth: 0-30 points (listings, bookings, chats, reviews)
     • Transaction history: 0-25 points
     • Labels: hot (80+), warm (60+), lukewarm (40+), cold (20+), inactive

 11. SECURITY IMPLEMENTATION
================================================================================

  1. AUTHENTICATION & AUTHORIZATION
     • JWT-based stateless authentication (access + refresh tokens)
     • Separate secrets for access and refresh tokens
     • Role-based middleware: authenticate, optionalAuth, requireAdmin
     • Banned user check on every authenticated request
     • Account deactivation check

  2. PASSWORD SECURITY
     • Bcrypt hashing with 10 salt rounds
     • Password field excluded from all queries by default
     • OTP codes excluded from query responses

  3. HTTP SECURITY HEADERS (Helmet.js)
     • Content Security Policy (CSP) with strict directives
     • X-Content-Type-Options: nosniff
     • X-Frame-Options: DENY
     • Strict-Transport-Security (HSTS)
     • Cross-Origin Embedder Policy

  4. CORS POLICY
     • Whitelist-based origin validation
     • Production mode: strict origin rejection
     • Development mode: permissive (all origins)
     • Credentials: enabled

  5. RATE LIMITING (6 tiers)
     ┌─────────────────┬───────────┬───────────────────────────────────┐
     │ Limiter         │ Max/Window│ Purpose                           │
     ├─────────────────┼───────────┼───────────────────────────────────┤
     │ authLimiter     │ 10/15min  │ Prevent brute-force login        │
     │ otpLimiter      │ 5/10min   │ Prevent OTP abuse                │
     │ listingCreate   │ 15/1hr    │ Prevent spam listings            │
     │ chatLimiter     │ 60/1min   │ Prevent message flooding         │
     │ reviewLimiter   │ 10/1hr    │ Prevent review bombing           │
     │ generalLimiter  │ 200/15min │ Global API protection            │
     └─────────────────┴───────────┴───────────────────────────────────┘

  6. INPUT SANITIZATION
     • XSS prevention via input sanitizer middleware
     • All request bodies, query params sanitized automatically

  7. SPAM DETECTION (3-layer middleware)
     • Duplicate listing detection (same make+model within 24h)
     • Content analysis (phone numbers, URLs, caps, short text)
     • Suspicious account flagging (3+ fraud reports)

  8. DATA VALIDATION
     • Sequelize model-level validations (email format, enums, ranges)
     • Environment variable validation on startup (validateEnv.js)

  9. SOFT DELETE
     • Paranoid mode (deletedAt column) on 8 tables:
       users, machinery_listings, part_listings, operator_profiles,
       mechanic_profiles, reviews, certification_requests, fraud_reports

  10. AUDIT TRAIL
     • Immutable activity_logs table (updatedAt disabled)
     • 30+ action types with severity levels (info, warning, critical)
     • IP address and user agent tracking

  11. ENVIRONMENT PROTECTION
     • .env validation before server starts
     • JWT_SECRET required in production (app crashes if missing)
     • Unhandled rejection and uncaught exception handlers

 13. DEPLOYMENT ARCHITECTURE
================================================================================

  Docker Multi-Stage Build (3 stages):

  Stage 1: Frontend Builder
    • Node 20 Alpine
    • npm ci + npm run build → produces /dist

  Stage 2: Backend Builder
    • Node 20 Alpine
    • npm ci --production → minimal dependencies

  Stage 3: Production Runtime
    • Node 20 Alpine (minimal image)
    • Non-root user (yantrasetu:1001)
    • Backend at /app/backend
    • Frontend static files served from /app/backend/public
    • Health check: GET /health (30s interval)
    • Port: 5000
    • NODE_ENV=production

  Database:
    • Production: PostgreSQL (with SSL, rejectUnauthorized: false)
    • Development: SQLite (local file: ./database.sqlite)
    • Auto-migration on startup (sync tables)

  Environment Variables Required:
    • DATABASE_URL (PostgreSQL connection string)
    • JWT_SECRET (required in production)
    • JWT_REFRESH_SECRET (optional, derived from JWT_SECRET)
    • FRONTEND_URL (CORS origin)
    • CORS_ORIGINS (comma-separated allowed origins)
    • PORT (default: 5000)
    • NODE_ENV (development/production)
    • RATE_LIMIT_* (optional overrides for all limiters)
